# Translations

Steward ships with skeletons for `en`, `es`, `fr`, `de`, `it`, `pt`.
Only English is filled in (it's the source language); the rest are
empty `.po` files waiting for translators.

If you want to translate, open a PR with the `.po` file. You don't
need a Python environment for that.

## Adding a new locale

1. Add it to `LANGUAGES` in `app/config/settings.py`.
2. Generate the catalogue:

   ```bash
   docker compose -f deploy/compose/docker-compose.yml exec -w /srv/app web \
       python manage.py makemessages -l <lang>
   ```

3. Translate the entries in `app/locale/<lang>/LC_MESSAGES/django.po`.
4. Commit the `.po`. The Docker image's build step runs
   `compilemessages`, so the `.mo` is regenerated on every build --
   `.mo` files are gitignored.

## Adding or changing strings

In Python:

```python
from django.utils.translation import gettext_lazy as _

label = _("Full name")  # model fields, choices, form labels
```

For runtime messages where laziness isn't needed:

```python
from django.utils.translation import gettext as _

messages.success(request, _("Member activated."))
```

In templates:

```django
{% load i18n %}

<h1>{% trans "Members" %}</h1>
<p>{% blocktrans with name=user.username %}Welcome, {{ name }}{% endblocktrans %}</p>
```

After changing strings, regenerate the catalogues so translators see
the new `msgid` entries:

```bash
docker compose -f deploy/compose/docker-compose.yml exec -w /srv/app web \
    python manage.py makemessages --all
```

## What gets translated

User-facing strings only:

- form labels, help text, validation errors;
- model `verbose_name`s and choice labels;
- `messages.*` calls in views;
- template text that renders to the page.

Not translated:

- log messages (the audience is operators, who read English);
- audit-log `note` / `target` payloads (machine-readable);
- error fallback text in `try/except` that won't reach the user.

## Translator workflow

A translator needs a `.po` editor (Poedit, Lokalize, VS Code's gettext
extension) and the `.po` file for their language. Edit, commit, open
the PR. CI compiles the `.mo` -- nothing else to do on their end.
